# 代码规范（ArkTS / ArkUI）

## 一、命名

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 文件（页面/组件） | 大驼峰，页面目录内 `index.ets` 汇总导出 | `NotesWaterFlow.ets`、`views/HomePage/index.ets` |
| 工具类文件 | 小驼峰 | `dateUtil.ets`、`validator.ets` |
| 结构体 / 类 | 大驼峰 | `HomePage_head`、`MyDataSource` |
| 常量 | 全大写下划线 | `ROUTE_LOGIN`、`STORAGE_KEY_USER` |
| 布尔变量 | `is` / `has` / `show` 前缀 | `isLoading`、`showRightIcon` |
| 事件回调 | `on` + 动词 | `onclick`、`onRefreshing` |

> 历史代码中 `onclick`（全小写）与 `onClickBack` 并存，新代码统一使用 `onXxx` 形式；
> 存量文件不做大规模重命名，避免无意义的 diff 噪音。

## 二、目录与导出

1. 每个目录提供 `index.ets` 作为统一出口，外部只允许 `import { X } from '../commons/utils'`。
2. 新增页面必须同步在 `entry/src/main/resources/base/profile/main_pages.json` 注册，否则路由跳转失败。
3. 新增组件必须同步在 `commons/components/index.ets` 追加 `export *`。
4. 新增工具类必须同步在 `commons/utils/index.ets` 追加 `export *`。

## 三、组件编写

```ts
@Component
export struct HcExample {
  // 1. 状态声明置顶，按 @StorageProp → @Prop → @State → @Link 顺序
  @StorageProp('topHeight') topHeight: number = 0
  @Prop title: string = ''
  @State isLoading: boolean = false

  // 2. 回调统一以 = () => {} 形式给出默认空实现，避免父组件未传时报错
  onclick = (index: number) => {
  }

  // 3. @Builder 私有方法置于 build 之后
  build() {
    Column() {
      Text(this.title)
    }
  }
}
```text

约束：

- `@Prop` 只接收不可变的基础类型或浅拷贝对象；需要双向绑定用 `@Link`。
- 组件内禁止 `router.pushUrl`（`auth.CheckAuth` 除外），跳转逻辑交由页面编排。
- 组件内禁止直接 `httpReq`，数据由父级下发；仅 `NotesWaterFlow` 这类「自带分页」的容器例外，并需在注释中说明。
- 列表统一使用 `LazyForEach` + `IDataSource`，`ForEach` 仅用于固定长度的少量数据。

## 四、异步与错误处理

1. 所有 `await httpReq.request` 必须包裹 `try / catch`，catch 中给出用户可感知的提示。
2. `catch (err)` 必须把 `err` 转为可读信息后再 `logger.error`，禁止直接吞掉。
3. `setInterval` / `setTimeout` 返回值统一用 `number` 接收，并在 `aboutToDisappear` 中清理。
4. 页面级请求需有 loading 态（`HcLoadingDialog` 或骨架屏）与空态。

## 五、样式

1. 颜色优先引用 `$r('app.color.xxx')`，临时色值允许字面量但需成组出现。
2. 尺寸使用 vp 默认单位，字号显式写 `fp` 时需说明原因。
3. 禁止在 `build()` 中写复杂表达式，抽成方法或 `@Builder`。

## 六、提交规范

采用 `type(scope): subject` 形式，type 取值：

| type | 含义 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档 |
| `refactor` | 重构（不改变外部行为） |
| `test` | 测试 |
| `chore` | 构建 / 依赖 / 杂项 |

示例：

```
feat(utils): 新增日期格式化工具类
fix(components): 修复验证码倒计时重置为 3 秒的问题
docs: 补充项目架构说明
```text

## 七、注释

- 对外导出的类与函数必须有块注释说明用途。
- 行内注释解释「为什么」而不是「做了什么」。
- 中文注释与英文注释不混用，存量中文注释保持中文。
